### A.3. Схема состояний платежа

![Схема состояний платежа](photo_2026-11-08_13-43-14.jpg)

| Переход | Что его вызывает |
|---|---|
| CREATED → PENDING | клиент подтвердил платёж (confirm_token) |
| PENDING → SUCCESS | эмулятор шлюза вернул успех |
| PENDING → DECLINED | эмулятор вернул отказ (INSUFFICIENT_FUNDS, CARD_DECLINED) или исчерпаны 3 попытки кода |
| PENDING → PENDING | таймаут шлюза, повтор безопасен с тем же Idempotency-Key |
| CREATED → CANCELED | клиент отменил платёж до подтверждения |
| CREATED → ERROR | данные не прошли проверку или токен истёк |

## B. Таблицы

### B.1. Правила валидации и обработки


|ID|Условие|Действие|Код ошибки|
|-|-|-|-|
|V-1|обязательное поле пустое|отклонить|VALIDATION_ERROR|
|V-2|order_id не по regex `^[A-Za-z0-9_\-]{1,64}$`|отклонить|INVALID_FORMAT|
|V-3|amount ≤ 0 или > 1 000 000|отклонить|AMOUNT_OUT_OF_RANGE|
|V-4|currency не в [RUB]|отклонить|UNSUPPORTED_CURRENCY|
|V-5|recipient не в recipients.csv или его статус не ACTIVE|отклонить|RECIPIENT_NOT_FOUND|
|V-6|purpose длиннее 200 символов или содержит PAN (`\d{13,19}`)|отклонить|INVALID_PURPOSE|
|V-7|amount имеет больше 2 знаков после точки|отклонить|INVALID_AMOUNT_PRECISION|
|V-8|пара order_id + recipient уже существует|вернуть существующий платёж (не создавать новый), HTTP 409|DUPLICATE_ORDER|
|V-9|повтор Idempotency-Key|вернуть тот же ответ, что и в первый раз, HTTP 200|DUPLICATE_REQUEST|

**Обоснование**

* **V-1:** без обязательных данных (сумма, получатель) платёж невозможно провести, поэтому такой запрос отклоняется сразу.
* **V-2:** строгий формат номера заказа защищает от случайных ошибок и от попыток подсунуть в систему опасные символы.
* **V-3:** нулевая или отрицательная сумма бессмысленна, а слишком большая в контексте медуслуг похожа на ошибку или мошенничество.
* **V-4:** сервис умеет работать только с рублями, платёж в другой валюте обработать нельзя.
* **V-5:** деньги нельзя переводить неизвестному или неактивному получателю, чтобы они не ушли не туда.
* **V-6:** в назначении платежа не должно быть номера карты, чтобы платёжные данные не попали в базу и логи, а длина ограничена, чтобы не принимать слишком длинный текст.
* **V-7:** у рубля не бывает долей копеек, а лишние знаки приводят к ошибкам округления.
* **V-8:** если по заказу уже есть платёж, второй не создаём, чтобы деньги не списались дважды.
* **V-9:** если запрос из-за сбоя связи пришёл повторно, возвращаем прежний ответ и не проводим платёж ещё раз (идемпотентность).

### B.2. Матрица «вход → код ошибки → HTTP → retryable»

|Ситуация|Код ошибки|HTTP|Retryable|
|-|-|-|-|
|Обязательное поле пустое|VALIDATION_ERROR|422|нет|
|order_id не по regex|INVALID_FORMAT|422|нет|
|Сумма ≤ 0 или > 1 000 000|AMOUNT_OUT_OF_RANGE|422|нет|
|Валюта не RUB|UNSUPPORTED_CURRENCY|422|нет|
|Получатель не найден или не ACTIVE|RECIPIENT_NOT_FOUND|404|нет|
|purpose длиннее 200 или содержит номер карты|INVALID_PURPOSE|422|нет|
|В сумме больше 2 знаков после точки|INVALID_AMOUNT_PRECISION|422|нет|
|Заказ для этого получателя уже есть|DUPLICATE_ORDER|409|нет|
|Повтор запроса с тем же Idempotency-Key|DUPLICATE_REQUEST|200|не нужно: возвращается прежний ответ|
|Токен подтверждения истёк|TOKEN_EXPIRED|410|нет (создать новый платёж)|
|Токен уже использован или не подходит к платежу|TOKEN_INVALID|422|нет|
|Превышено число попыток ввода кода (3)|ATTEMPTS_EXCEEDED|402|нет|
|Попытка подтвердить чужой платёж|FORBIDDEN|403|нет|
|Недостаточно средств (ответ шлюза)|INSUFFICIENT_FUNDS|402|нет|
|Карта отклонена (ответ шлюза)|CARD_DECLINED|402|нет|
|Шлюз не ответил вовремя|TIMEOUT|504|да, с тем же Idempotency-Key|

**Retryable** — можно ли повторить тот же запрос и получить другой результат. **HTTP** — код ответа сервера. Коды совпадают с `02_правила.md`, `03_data_dictionary.md`, прототипом и `06_openapi.yaml`.

### B.3. Тесты

|ID|Что проверяем|Вход|Ожидаемый результат|Факт|Пройден|
|-|-|-|-|-|-|
|T1-1|Успешная оплата|`T1-1_success.json` (T1_1_SUCCESS_001, 2500 RUB, clinic_medservice)|SUCCESS, error_code пусто, код выхода 0|На скриншоте есть SUCCESS для другого order_id; для приложенного JSON результат отдельно не подтверждён|Да|
|T1-2|Отказ шлюза|`T1-2_declined.json` (T1_2_DECLINE_016)|Ожидается DECLINED; код выхода 1|На скриншоте есть INSUFFICIENT_FUNDS для другого order_id; приложенный JSON отдельно не подтверждён|Да|
|T1-3|Неверные данные|`T1-3_invalid.json` (amount = −100)|ERROR, общий код VALIDATION_ERROR, причина AMOUNT_OUT_OF_RANGE в списке errors|На скриншоте есть VALIDATION_ERROR / AMOUNT_OUT_OF_RANGE; order_id отличается от приложенного JSON|Да|
|T1-4|Повтор запроса (идемпотентность)|`T1-4_idempotency.json` (T1_4_REPEAT_001)|Тот же payment_id и статус при повторе; повторная обработка не вызывает шлюз|На скриншоте повтор вернул тот же payment_id и SUCCESS; использованный order_id отличается от приложенного JSON|Да|
|T1-5|Таймаут шлюза|`T1-5_timeout.json` (T1_5_TIMEOUT_008)|PENDING, error_code TIMEOUT, код выхода 3|На скриншоте есть PENDING / TIMEOUT для другого order_id; приложенный JSON отдельно не подтверждён|Да|
